## Requirements
### Requirement: SW09 有界后台工作

系统 MUST 满足以下规则：随任务启动的有界后台执行器继续处理已登记且获授权的辅助工作，队列处理完退出；前台结束和 Task 完成不丢弃工作。遵守 Stop、范围、各自预算和在途对账；首期无永久服务/开机自启要求，关机不承诺执行，下次启动先恢复事实。

追踪：SW09 / AC09。

#### Scenario: AC09 验收行为

- **WHEN** 已登记辅助工作遇前台关闭/Task 完成
- **THEN** 后台可继续；队列完成退出；关机后再启动先对账，Stop 不被解除

### Requirement: SW18 Task memory

系统 MUST 满足以下规则：原始报告、决定和阶段事实跟随 Task，Session memory 只是投影。已接受成果与进行中/失败内容分区；摘要不能代替授权、计数或人工决定。实质成果/决定/待办/风险变化才刷新，派发前核对来源，新 Session 从 Task 重建；迟到旧摘要不得覆盖新视图。摘要不可用不撤销接受/完成，必需原始工件完整可降级，否则仅暂停受影响派发；不得覆盖人工原文。

追踪：SW18 / AC18。

#### Scenario: AC18 验收行为

- **WHEN** 摘要失败但必需原始资料完整
- **THEN** 降级继续；必需资料缺失 → 暂停相关派发；无实质变化不调用，换 Session 重建，晚到旧摘要不覆盖人工/新视图

### Requirement: SW19 辅助恢复统一边界

系统 MUST 满足以下规则：memory、知识提取、知识汇总和 Verifier 各对固定输入最多追加一次恢复，不自动升级。确定终止无可复用结果重调、无效输出重生成、有效结果重存共用原额度；未知先核实，不通过重启/新 Task 引用相同历史输入刷新额度。耗尽标不可用，不重开实现/测试或阻塞其他安全工作。此规则不适用于通知、报告补交、诊断或 Coder/Tester 修复。

追踪：SW19 / AC19。

#### Scenario: AC19 验收行为

- **WHEN** 分别对四类辅助步骤：确定终止无结果/无效结果/有效结果保存失败
- **THEN** 共用一次追加恢复；相同输入重启/跨 Task 引用不刷新，未知先核实，耗尽非开发 Gate

### Requirement: R1 辅助登记与来源账本恢复

系统 MUST 从已持久提交的接受或完成事实登记辅助工作，使用操作类型、不可变来源身份及输入摘要去重。来源登记和对应消费游标推进 MUST 位于同一可恢复提交。不同 Task 引用同一来源时 MUST 使用同一来源恢复账，不能复制或刷新额度；来源账不可读只限制依赖它的辅助工作，不撤销已有开发接受。

此要求细化 SW09/SW18/SW19，追踪 AC09/AC18/AC19、AX02。

#### Scenario: 接受完成但辅助登记中断

- **WHEN** 接受事实已提交，辅助登记尚未完成或游标确认中断
- **THEN** 恢复从固定来源补登记同一工作；重复恢复不丢任务、不新增同输入的执行额度，也不撤销接受

#### Scenario: 其他 Task 再次引用同一输入

- **WHEN** 另一 Task 引用已有来源和输入摘要，原辅助恢复额度已使用或账本暂不可读
- **THEN** 继续引用原账；已用额度保持已用，不可读时记录辅助缺口，不以新 Task 建立零计次替代账

### Requirement: R3 辅助资源准入与持久累计

系统 MUST 在派发前按版本化资源政策核验完整输入、输出、实际模型能力、队列、宿主与存储预约。首期单次输入不超过 32,768 tokens 且 128 KiB，输出不超过 4,096 tokens 且 64 KiB；Task 辅助累计不超过 524,288 tokens 和 64 次实际派发。能力或计量未知不得猜测余额或容量；未知派发保留预约，确认未派发才释放。项目辅助并发为 1，单 Task/项目非终态队列分别为 128/1,024。跨 Task 同输入 MUST 复用唯一来源账，拆批/重启不新增额度。存储 Task/项目新辅助内容上限为 512 MiB/4 GiB，写入预约后卷余量至少 256 MiB；未知或不足停止受影响写入，不删历史。其余计量口径遵循 R3 资源政策。追踪 SW09/SW18/SW19/SW27、AC09/AC18/AC19/AC27。

#### Scenario: 模型容量与使用量未知
- **WHEN** 实际模型缺可靠能力记录，或派发后没有可靠 usage/终态
- **THEN** 前者不调用该辅助模型，后者保留原预约；不猜 token、不补零、不影响已有开发接受。

#### Scenario: 队列或存储达到上限
- **WHEN** 排队数量超额、存储峰值预约超额或卷余量未知/不足
- **THEN** 不派发对应新工作，保留未消费来源/等待事实；不能推进游标冒充登记成功或自动删除证据。

#### Scenario: 多 Task 同时引用相同来源
- **WHEN** 两个 Task 请求相同固定输入且原恢复额度已使用
- **THEN** 共享原来源结果/恢复账，唯一派发预约不会重复创建；每个消费者仍受自身历史扫描上限约束。
