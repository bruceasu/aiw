## Requirements
### Requirement: SW20 提取与汇总

系统 MUST 满足以下规则：Work Item 接受时登记异步提取，Task 完成事实保存后异步汇总且不等待。记录可复用规则/决定/经验、来源和证据性质，允许有依据的“无新增”；未成功提取不能记无新增。只从已有失败证据提取观察，不因每次失败新增提取循环。失败状态与开发完成分开。

追踪：SW20 / AC20。

#### Scenario: AC20 验收行为

- **WHEN** 恢复旧 Task 的计数或继续运行
- **THEN** 接受登记提取，Task 完成先保存并通知再异步汇总；提取失败不撤销完成，也不记“无新增”；真实空结果可明确无新增

### Requirement: SW21 部分覆盖及版本

系统 MUST 满足以下规则：汇总列明应覆盖的 Work Item、成功/运行中/失败/缺失状态及条目来源；可发布带明确缺口的部分草稿。补齐或来源实质变化生成新版本，不覆盖人工编辑/审阅、不继承新正文的旧确认；不变条目保留本版本确认，不因整份汇总升级而全量重批。

追踪：SW21 / AC21。

#### Scenario: AC21 验收行为

- **WHEN** 一项提取失败时发布部分草稿
- **THEN** 缺口可见；补齐新版本不继承新正文确认，未变条目仍保留原确认

### Requirement: SW22 知识五态与审阅

系统 MUST 满足以下规则：以条目版本为审阅单位，支持候选、已确认、待复核、已拒绝、已废弃；部分条目可确认。操作条件绑定所见版本，版本冲突不得静默覆盖。人工编辑产生新候选，可明确确认新版本；记录主体/时间/来源和历史。仅人工确认/拒绝/废弃或建立替代关系；废弃不以已有替代为前提，重复输入不得绕过拒绝。

追踪：SW22 / AC22。

#### Scenario: AC22 验收行为

- **WHEN** 同一汇总部分条目确认，另一审阅基于旧版本提交
- **THEN** 不静默覆盖；编辑产生新候选；拒绝重复输入不改号绕过，废弃可无替代

### Requirement: SW23 失效及复核

系统 MUST 满足以下规则：关联变化异步标待复核，读取时再核对，不能检测时明确说明，不自动判错/废弃。正文、关联来源及范围未变可在原版本追加人工复核；正文、绑定来源版本、证据性质、范围、使用方式或失效条件实质变化生成新候选，即使结论文字相同也不继承确认。无关文件、显示顺序、时间戳变化不升级版本。只有人工复核可恢复主参考。

追踪：SW23 / AC23。

#### Scenario: AC23 验收行为

- **WHEN** 关联版本变化而结论相同
- **THEN** 原版待复核，新版候选；同来源临时不可读后恢复原样 → 可人工复核原版；无关时间戳不新版本，读取时捕获异步未标差异

### Requirement: SW24 人工介入及文档边界

系统 MUST 满足以下规则：优先已指定负责人，否则当前项目操作者；身份未验证明确标注，不授额外权限。旧 Session 唯一人工文本保留原文/来源导入候选，可关联可核实正式决定则直接引用；不确定且影响执行时集中询问。普通知识审阅进待办而不阻塞开发；仅无法安全满足当前需求/验收/授权时请求裁决。知识确认不自动同步 CONTEXT、ADR、需求、代码等，首期只记录建议同步及来源。

追踪：SW24 / AC24。

#### Scenario: AC24 验收行为

- **WHEN** 无指定负责人/无可验身份
- **THEN** 当前操作者且明确标识；旧文本保原文成候选，可核实决定直接引用；普通审阅不阻塞且确认不写正式文档

### Requirement: SW26 知识选择与冲突

系统 MUST 满足以下规则：首期按模块/路径/接口/领域标签和少量通用规则可复现地选择，可信状态分区。已确认且适用可作主参考；候选/待复核带警示作次要参考，不能单独驱动实现或验收；拒绝/废弃不自动注入。主来源优先，普通知识冲突只降级/记录；无法安全满足主来源、兼容或授权边界才转人工，不因偏好分歧阻塞。

追踪：SW26 / AC26。

#### Scenario: AC26 验收行为

- **WHEN** 同输入重复选择
- **THEN** 可复现；拒绝/废弃不注入；知识与需求冲突但主来源可安全满足 → 降级继续，否则集中人工裁决，不改验收

### Requirement: SW27 资源及历史范围

系统 MUST 满足以下规则：必需输入优先不可截断；可选知识超预算按确定顺序跳过并记录。当前需要时自动回填相关模块/接口/依赖的历史知识并作只读补审，先复用已有结果；单批及当前 Task 累计硬上限，拆批/重启不刷新，超限不自动扩额，可选工作停止、其他安全开发继续。首期不按保留期自动删除证据，空间不足暂停受影响写入并提示。具体 token/批量/存储参数由工程设计在对应能力实施前确定并记录，这是 D16-E 唯一明确获准的参数后续细化分工。

追踪：SW27 / AC27。

#### Scenario: AC27 验收行为

- **WHEN** 恢复旧 Task 的计数或继续运行
- **THEN** 只回填当前相关历史；拆批/重启达到累计上限仍停止可选工作；必需输入不截断，空间不足不删历史；实施前参数有依据/硬上限

### Requirement: R3 历史与知识注入额度

系统 MUST 采用 R3 版本化参数：单批历史最多 16 个来源且合计 1 MiB，当前 Task 累计最多 64 个不同来源且合计 4 MiB；可选知识注入最多 16 条、4,096 tokens 且 16 KiB，并占接收方完整输入预算。按可信状态、相关性、优先级和稳定 ID 确定性选择，超额整条跳过并记录原因；必需正文不截断。提取、汇总及恢复共用 Task 辅助累计与来源账，不因拆批、模型别名或换 Session 重置。此要求细化 SW26/SW27、AC26/AC27、AX05。

#### Scenario: 历史分批达到累计上限
- **WHEN** 单批仍有空间但 Task 的历史来源数或字节累计已到上限
- **THEN** 停止自动回填，保存缺口并继续其他安全工作；重启或另拆批不扩大额度。

#### Scenario: 可选知识挤占必需输入
- **WHEN** 已选知识将使完整输入超额，或其 token 无法可靠计量
- **THEN** 跳过可选条目并说明原因，保留必需原文；必需输入自身超额时只停止受影响派发。
