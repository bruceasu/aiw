# Task 列表识别设计

## Context

`internal/commands/task/workflow.go` 的 listTasks 仅检查目录类型，再调用 ResolveTaskMetaPath / ReadTaskMeta；任意读取错误都会输出 UNKNOWN。`internal/taskx/meta.go` 支持 `.ai/<id>/`、旧 `.ai/tasks/<id>/` 和 task.toml / tasks.toml，但读取成功本身不保证 ID 非空。

静态目录检查显示，用户误列的七种内部目录没有 task.toml；真实 Task 目录有对应文件。已有 task-lifecycle 规格要求保留旧路径兼容。

## Goals / Non-Goals

**Goals:** 准确识别 Task、明确错误、保留兼容及正常行格式、用命令输出回归锁定症状。

**Non-Goals:** 运行数据迁移、自动修复元数据、目录名黑名单、全局 TOML 解析改造、改变 Workflow 状态推导。

## Design Readiness

FD_NOT_REQUIRED。本次是已定位的局部列表缺陷，目录身份判断和错误分类已明确，无新增持久化、依赖或并发机制。错误报告的具体契约如下，实施前无需独立 FD 生命周期。

## Decisions

### 发现以元数据为依据

在规范运行根下检查直接候选目录，并在已支持的旧 Task 根下检查一层候选。普通文件和没有 task.toml / tasks.toml 的目录不构成 Task；不递归扫描 Session、缓存或任意后代目录。不要求存在 OpenSpec 目录才认定已有 Task，避免掩盖工件丢失。

使用 taskx 的现有解析优先级：规范目录优先，规范目录不存在时才回退旧位置；同一目录 task.toml 优先于 tasks.toml。同 ID 只列一次，按候选 ID 排序。规范记录存在但损坏时不可用旧副本掩盖错误。

### 不存在与错误分开

先对候选元数据作可区分错误原因的文件检查。两个受支持文件均不存在时跳过；权限、I/O 或元数据路径不是普通文件时诊断。元数据已被识别后发生读取失败也诊断，不冒充不存在。

读取后至少检查 ID 非空、合法且与候选目录身份一致。保持现有解析器及兼容字段规则，不为本修复引入完整 TOML 重构。

有效记录继续通过现有 workflowSummaryForMeta 显示派生状态；其失败保留 RUNTIME_ERROR 行。Task 元数据错误写 stderr，包含实际路径与原因，不输出正常 Task 行。继续列出其他有效记录，最终返回汇总错误使退出码非零。普通目录被跳过不导致失败；空列表不生成 UNKNOWN 行。根目录枚举失败保持错误返回。

### 测试边界

主要边界为 Task 命令 list 入口，在临时仓库 fixture 内运行实际发现、解析和输出逻辑，捕获 stdout、stderr 及返回错误；不测试私有循环实现细节。优先复用已有命令测试中的仓库根与输出捕获设施；权限类错误若平台不可稳定制造，使用窄文件读取替身，不改变系统权限。

输入包括用户列出的内部目录、任意未来内部目录、正常 DRAFT/DONE Task、空/缺 ID/ID 不符的元数据、元数据路径为目录、旧路径和旧文件名、规范/旧副本重复、Workflow 摘要错误及仅有内部目录。断言正常记录集合、排序、错误通道和退出结果；仅断言字符串不出现不足以证明正常 Task 未被丢失。

## Risks / Trade-offs

- [损坏记录现在导致非零退出码] → 保留其他有效输出，文档明确诊断语义，避免脚本误认为列表完整。
- [宽松旧解析器不检测全部 TOML 语法错误] → 本修复保证文件错误和身份错误可见，不声称完整语法验证。
- [旧路径与规范目录冲突] → 遵守既有优先级并明确诊断，不自动迁移或选择较新文件。

## Migration Plan

无需迁移或清理。部署修复后的 CLI 即使用新发现规则，已有生命周期记录保持原样。
