## Why

Task 的 OpenSpec 文档与 AIW 运行数据属于同一生命周期。当前归档只移动 change，运行目录仍留在活动位置，导致普通列表继续显示已归档任务，且输出的 change 路径可能已经不存在。

列表使用固定最小列宽，较长的 Task ID 会挤乱状态列。需要按实际内容对齐，并在支持颜色的交互终端突出状态。

## What Changes

- 修复归档：同时移动规格目录和任务运行目录，使用相同的日期与任务 ID。
- 将 Task 实际绑定的 Session 纳入同一次归档，保留会话内容、身份与引用，支持归档后查询及失败恢复。
- `aiw list` 只显示未归档任务；新增 `aiw list --all`，同时显示已归档任务、归档标识及真实路径。
- 保留任务完成/取消状态，将是否归档作为独立信息。
- 识别历史上只归档 change 的任务；列表不移动已有记录，通过再次显式执行该任务的 archive 修复配对。
- 原生与 OpenSpec 委托归档遵守相同的配对契约，移动失败必须恢复或明确报告恢复失败。
- 优化 list 和 list --all 的表格：动态列宽、清晰表头、状态配色；管道、重定向和禁用颜色环境输出无 ANSI 的纯文本。
- 规格记录缺失时保留任务行并显示“规格已删除”，不因该缺失使列表失败。
- 合并规格与运行目录中的任务候选；运行记录缺失时自动补建最小记录并继续显示，不恢复未知执行历史、不启动任务。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `task-lifecycle`：增加配对归档、归档任务枚举和历史配对修复要求。

## Impact

影响任务归档、运行数据定位、列表参数和显示、相关帮助与文档。保留现有归档资格、Git 交付授权和旧元数据兼容规则。不自动提交、创建工作树、批量迁移或删除运行记录。

## User Stories

1. 作为使用者，我希望一次归档能同时保存规格与运行记录，避免目录生命周期分离。
2. 作为使用者，我希望普通列表只显示未归档任务，便于查看当前工作。
3. 作为使用者，我希望用 `--all` 查到历史任务及真实归档路径。
4. 作为使用者，我希望历史任务仍保留原有完成或取消状态。
5. 作为使用者，我希望归档失败时能看到准确的恢复信息，且不会覆盖已有记录。
6. 作为使用者，我希望旧版留下的半归档任务可以通过显式操作修复。
7. 作为使用者，我希望长任务名和长状态仍能整齐对齐，并能通过颜色快速区分完成、等待和异常。
8. 作为使用者，我希望规格记录丢失时，输出规格已经删除，而不要出错。
9. 作为使用者，我希望运行记录丢失时，自动构建个运行记录，而不要出错。
10. 作为使用者，我希望任务对应的 Session 随任务一起归档，归档后仍能查询会话记录。
## Out of Scope

任意深度递归搜索、与本 Task 无关的独立 Session 批量迁移、自动批量迁移、恢复归档任务为活动任务、允许重复使用历史 Task ID、Git 自动交付，以及修改现有 Task 完成资格。
