# R3 辅助资源与历史处理上限

2026-09-18，按用户“继续推进”授权补齐工程参数。FD_APPLIED；本文件属于 design.md，服务 E05/E06/E08，追踪 SW09/SW18–SW27/SW31/SW32、AC09/AC18–AC27/AC31/AC32、AX04/AX05。参数是首期工程保护值，不是模型容量、计费承诺或已测性能。

## 依据与适用范围

`internal/ai/config.go` 的 Profile 只有 Name/Provider/Model；当前 Task routing-plan 使用 fast/balanced/reasoning 的默认角色映射，没有可靠 token 容量证明。E01 的 128 来源文件、4 MiB 正文和最终 prompt 上限是同步输入字节保护，不是模型 token 限制，也不能替代本政策。

本次静态样本：需求正文 21,586 字节、验收追踪 13,185 字节、工程交接 17,670 字节、需求计划 16,326 字节；设计文件当时 34,369 字节。128 KiB 足以容纳这组主文档规模，但不保证任意源码/diff/所有角色输入都能放入。采用按 Work Item 固定必需输入、可选输入确定性筛选，禁止通过截断必需资料来凑合限额。模型能力未知必须显式等待，而不是凭字节比估算 token 后自动调用。

资源政策保存为项目运行目录 `.ai/resource-policy.json` 的版本化记录，并在 Task 首次使用时冻结其摘要。这里只定义未来实现，不创建实际配置或启用后台工作。源账、Task 累计和项目存储由 Core 管理，Session 及展示配置不拥有计次权。

token 上限仅约束上述辅助生成，不能用来减少已批准的 E04 Coder/Tester 修复次数。通知不消费模型 token，但使用队列、存储和宿主槽；通知发送及等待规则仍归 E07。只读结果复用不计模型调用，新的历史来源登记仍计本 Task 的来源范围预算，防止借复用无限扩展扫描。

## 计量与模型能力契约

适配器针对实际 provider/model 固定 capability 引用：上下文容量、输出上限、计数方法版本、封装开销、强制输出限制能力。必须有可核实本地能力记录和匹配的计数器，或有依据的保守上界；无此依据返回 capability-unavailable，不联网探测、不下载 tokenizer、不猜“每字符几个 token”。项目不能用 Profile 别名绕过实际模型约束。

派发须满足完整输入计数 + 预约输出不超过模型上下文容量，并分别不超过模型/政策限制。模型能力低于政策时取较小值；能力未知、输出限制无法强制或间接工具可能引入未计量输入时停止相关辅助调用。R3 的 token 数不是费用上限，未取得模型计费和使用数据前不报告金额。

每次派发前在来源账与 Task 预算中原子预约完整输入计量值及最大输出；确认派发后次数不退。可靠 usage 保存后按实际量结算，缺失 usage 或启动结果未知则保留满额预约，不补零。确认未派发才释放原预约，不能通过重启重建余额。超限输出按无效结果处理，只允许 SW19 原固定输入的一次追加恢复；不得为规避额度偷偷拆分同一操作为多个请求。合法 failed/inconclusive Verifier 结论不是生成失败。

## 累计账、跨 Task 及存储

操作键为类型 + 不可变来源身份 + 输入摘要；来源所有 Task 持有执行恢复账，引用方不复制余额。引用已有结果不重复派发；首次需要对同一源执行的消费者在来源锁内登记唯一赞助 Task 与预约，其他消费者等待/复用，不得并发建立第二份账。实际使用计入赞助 Task 并留来源关联；该 Task 已完成也不刷新来源恢复额度。当前消费者自己的历史扫描限额仍计所选来源。

多个账/状态文件不能声称跨文件原子：采用 R1 持久意图和稳定预约 ID，先可靠预约来源/项目额度再允许 Task 记派发；未知预约保留并对账，结果只消费一次。项目资源锁只在核验和更新账时持有，不跨模型调用；锁顺序固定项目资源 → 来源 Task → 消费 Task，同一 Task 去重且多个 Task ID 字典序，避免交叉等待。此协议由 E05 集成 R1；不另建可绕过 Core 的独立计次器。

Task 累计使用只增记实际消费，降低政策上限立即影响新派发；提高上限须显式政策变更并留原因/版本，绝不重置旧使用或自动扩额。未能重建旧预算/来源/存储计量时标 unknown，暂停相关辅助工作而不撤销开发接受。历史文件超过新上限保留原件，仅拒绝新的受影响分配。

存储账按唯一物理工件归属计量；引用不重复收费于存储账，复制文件则重新占用。每次写入前预约峰值新增字节，提交后释放临时预约并核对实际内容；多 Task 合计用项目账串行核验。预留控制记录空间计入硬上限，业务负载不得占满；控制记录追加失败时停止派发，下次按已有意图恢复。外部磁盘占用仍可能造成失败，256 MiB 只作预检余量，不宣称已保证写入成功。

## 有界宿主与降级

队列为空或仅有不可执行 waiting/reconcile 项时退出；未来通知到期在本宿主剩余预算内可等待，否则持久保存 due time，待下次受管启动恢复，不承诺精确到秒或关机执行。排队满额以未消费持久来源补登记，必须先成功登记或明确记录终态不可用再推进对应游标。来源游标缺口不撤销已接受成果。

memory 不可用但必需原文齐全时降级；原文不足仅阻塞依赖它的派发。知识超限跳过可选内容；Verifier 超限记录无法执行，不给空 passed。存储不足停止实际受影响写入、保留证据并通知本地操作者，不通过自动清理恢复。
