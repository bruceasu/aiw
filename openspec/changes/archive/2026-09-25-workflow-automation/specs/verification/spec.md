# verification：自动化开发工作流变更

来源：[已批准 Requirement Plan](../../../../../docs/requirements/REQ00001-workflow-automation/requirement-plan.md)。以下是拟交付规范与待执行验收；按 Plan 后续确认覆盖旧来源中的人工计划审批和通知重试规则。未列出的稳定规格条款保持不变。

## REMOVED Requirements

### Requirement: 三次连续编译失败上限

**Reason:** SW16/SW17 已用按生成请求归因的角色失败/升级和共享六次修复替换旧缺陷阈值及成功清零规则。
**Migration:** 保留旧记录，按可核实证据迁移预算；未知不归零、不伪记耗尽，集中请求额度决定。旧授权按原语义处理。

## MODIFIED Requirements

### Requirement: 冻结 Compile Plan

监督请求 MUST 使用冻结 Compile Plan、编译输入和结果引用；必需编译计划缺失不能当作通过。Compiler 使用受支持脚本或适配器。修复新请求保存新的输入版本，旧请求不得回写；结果复用须通过 SW03 适用性核验。

#### Scenario: 修复改变输入
- **WHEN** 实现、测试、相关配置或计划的实际内容改变
- **THEN** 旧通过仅作历史，重新执行适用编译；不以相同 HEAD/状态字母推断未变。

### Requirement: Verification Plan 绑定的聚焦测试

系统 MUST 区分获批范围/发现规则/执行约束与本次清单/输入摘要，AI grant 绑定前者而每次执行记录绑定后者。固定选择计划限定 check_id、argv、目录、超时、profile 和环境。范围内新增测试不逐例重批，但旧通过失效；实质计划、目标或危险副作用变化须新授权。旧 digest/consumed 契约不被扩大或复活。

#### Scenario: 授权内发现
- **WHEN** 新测试处于 AI 批准的发现范围内
- **THEN** 核验后以新清单运行，不要求用户逐例批准，不复用旧执行证据。

### Requirement: 测试执行证据与网络约束

Runner MUST 校验网络、目录、实际路径、副作用及资源限制，保存退出码、超时、输出、计划/grant 和输入版本。无法满足宿主约束时不得静默放宽。N/A、未执行、waived、failed 和 passed 分开；旧可选 waived 不满足必需测试。

#### Scenario: 无法强制禁止网络
- **WHEN** 宿主不能满足 network=deny 且没有适用政策授权
- **THEN** 阻止执行并说明环境缺口，不将其归为代码缺陷或测试成功。

### Requirement: Tester 编写与监督接入边界

系统 MUST 在编译通过、安全交接写入权后实际派发独立 Tester，装载需求、验收、报告、接口、源码、已有测试/fixture 及允许路径正文。按需求定义断言；编写产物与受控执行证据分别保存，修复不得删弱断言换通过。

#### Scenario: 实现偏离需求
- **WHEN** 当前实现与明确需求不同
- **THEN** Tester 以需求构造断言并登记缺陷，不能把当前实现当成正确答案。

### Requirement: Verifier 的 report-only 契约

系统 MUST 在接受时封存需求、验收、diff、实现与编译/测试证据，登记并实际异步派发只读 Verifier。报告保留 schema、Task/Work Item/Attempt、outcome、summary、时间及逐项覆盖依据。合法负面结论仍可成功保存；记录 accepted 不代表验收成功，不建立 Gate、撤销完成、阻断 delivery 或触发返工。

#### Scenario: 晚到负面报告
- **WHEN** 已接受版本的独立 Verifier 返回 failed
- **THEN** 保存并关联固定被审版本，当前开发完成及交付状态不因此反转。

## ADDED Requirements

### Requirement: SW03 证据有效性

系统 MUST 满足以下规则：编译与测试通过只能来自受控执行记录，不能来自 Agent 声明。当前接受须证明实现、测试/fixture、相关配置/依赖、计划、需求验收及适用范围一致；发生相关变化则旧通过证据失效。报告、日志、时间戳、memory 更新本身不使证据失效；不能仅凭 HEAD 或 Git 状态字母相同判定内容相同。

追踪：SW03 / AC03。

#### Scenario: AC03 验收行为

- **WHEN** 已通过后修改实现、测试、fixture、相关配置/依赖、计划或验收
- **THEN** 不复用旧通过；仅改日志/memory则不失效；同文件 M→M 仍检测内容变化

### Requirement: SW04 旧 Task 与下游读取

系统 MUST 满足以下规则：所有未完成 Task 采用新接受规则：适用且可核实的旧结果直接复用；仅缺报告按 SW02；缺有效证据按当前授权重新验证，缺授权则暂停相关执行。不可恢复理由标未知，不补造事实或强迫重写已有效代码。Tester 可读待接受的实现报告；依赖 Work Item 只能使用已接受且仍适用的成果。

追踪：SW04 / AC04。

#### Scenario: AC04 验收行为

- **WHEN** 恢复旧 Task 的计数或继续运行
- **THEN** 旧未完成 Task 有适用证据则复用，仅缺报告则补交，缺授权则不执行；Tester 读取未接受实现不使下游 ready

### Requirement: SW10 独立 Tester

系统 MUST 满足以下规则：编译通过后，Tester 在独立上下文中取得原始需求/验收、实现报告、接口清单、源码、已有测试/fixture 及范围约束，产出单元测试、用例清单和执行计划。预期行为以需求为准，不按当前实现反推断言；写入限获准测试路径，不与 Coder 并写。

追踪：SW10 / AC10。

#### Scenario: AC10 验收行为

- **WHEN** 实现与明确需求不一致
- **THEN** Tester 以需求写断言；请求含独立上下文/允许路径；越界修改不被接受

### Requirement: SW11 具体计划与自动发现

系统 MUST 满足以下规则：初始具体测试计划由 AI 按用户制定的政策批准或拒绝，授权保存于 .ai/<task-id>/grant.md。计划明确模块/路径、发现选择规则、执行约束及资源上限；授权范围内新增或修改测试/fixture 自动发现并使用新证据，不逐用例重批。实质计划、目标或副作用变化须由 AI 重新评估并登记授权；不明确则停止相关执行。旧固定选择计划保持原限制，不复活已消费的旧授权。授权不能突破宿主权限、受控命令及无网络约束。

追踪：SW11 / AC11。

#### Scenario: AC11 验收行为

- **WHEN** AI 已批准限定发现计划且新增范围内 fixture
- **THEN** 自动选择并执行并使旧证据失效，不逐例询问用户；旧固定选择不扩大，未授权/越界不执行

### Requirement: SW12 权限危险性与 LOG

系统 MUST 满足以下规则：Supervisor 按可解释且有版本的政策核对实际操作、路径/链接目标和副作用，由 AI 授权人对适用的新计划批准或拒绝。删除、项目外修改等危险变化不能沿用旧授权；未知操作不得默认放行。grant.md 至少记录日期、权限、原因、是否同意、授权人（user/ai）和申请人（流程环节）；用户负责政策调整，不参与逐次计划批准。明确安全且可靠保存 LOG 后继续；LOG 失败先对账，再共用所属阶段 SW07 原额度恢复，不另调模型或增加预算。操作、内容、目标或政策变化须重审。Git push 与直接 Git 删除仍受 SW33 的禁止规则约束，AI 不得自行豁免。

追踪：SW12 / AC12。

#### Scenario: AC12 验收行为

- **WHEN** 操作或真实链接目标改变、或 LOG 持久化失败
- **THEN** AI 重审适用计划并登记 grant；未知不放行，LOG 恢复沿用原阶段额度，禁止操作不得由 AI 豁免

### Requirement: R2 授权记录与执行清单契约

系统 MUST 以有版本且严格解析的结构化授权日志作为依据，保留批准、拒绝、替代和旧使用事实；执行请求引用精确条目及计划/政策摘要。重复字段、未知版本/字段、记录截断、冲突或未可靠提交的记录不得产生执行权限。日期或最新文件不得替代明确引用；后续拒绝/撤销不得因旧索引而遗漏。可授权范围与本次执行清单 MUST 分别冻结，范围授权不免除每次派发的 Stop、写入权、预算及宿主核验。旧固定计划不扩大，旧 consumed 不复活。此要求细化 SW11/SW12，关联 SW08/SW14 和 AX03。

#### Scenario: 授权文件存在歧义或未提交
- **WHEN** 文件含重复字段、未知版本、缺失历史或保存成功但 Core 尚未提交引用
- **THEN** 不从部分内容派发；保留原件并对账，同一决策重复登记不新增批准或调用额度。

#### Scenario: 批准后出现拒绝
- **WHEN** 请求引用的批准仍在文件中，但同一计划/能力已有后续拒绝或撤销
- **THEN** 停止新派发；只有明确替代冲突决定且符合当前政策的新批准才能重新授权，不选择时间最新条目猜测权限。

#### Scenario: 范围发现与旧固定计划
- **WHEN** 新发现计划增加范围内测试，或旧固定计划的命令/选择改变
- **THEN** 前者刷新执行清单与证据并重检预算；后者不得沿用旧批准，consumed 记录不得恢复有效。

#### Scenario: 实际目标或宿主约束变化
- **WHEN** 清单冻结后链接目标、程序、目录或副作用变化，或宿主无法可靠约束实际操作
- **THEN** 执行器在副作用前拒绝旧清单，记录 stale 或 host-unavailable；不通过重新批准绕过宿主约束。

#### Scenario: 接受候选失效
- **WHEN** Tester 已提交候选，但输入变化、编译/必需测试缺失或只有历史 waived
- **THEN** Core 不提交接受引用，不释放依赖；授权记录不能充当执行通过证据。

### Requirement: SW13 修复闭环

系统 MUST 满足以下规则：受控执行器保存退出码、超时、输出、计划与输入版本；缺陷回交责任 Coder 或 Tester，环境问题不靠改代码或升级解决，需求冲突转人工。Coder 不得删弱测试消除失败；Tester 修改须有依据并保留历史。修复后重新编译和相关测试，接口变化须检查用例适用性，次数遵守 SW16/SW17。

追踪：SW13 / AC13。

#### Scenario: AC13 验收行为

- **WHEN** 实现/测试/环境/需求四类失败
- **THEN** 分别回交或等待；修复后重编译和相关测试，不能删弱断言换通过

### Requirement: SW14 接受与不适用

系统 MUST 满足以下规则：有效报告、当前适用编译和单元测试证据满足后才接受并释放下游；清单勾选、Session 成功或 Coder completed 均不能绕过。明确不影响可执行行为的变更可按规则记录单元测试不适用，疑问转人工；执行型 prompt/配置/脚本不按纯文档处理。不适用、未执行、waived 与 passed 分开，旧可选测试 waived 不能替代新的必需测试。

追踪：SW14 / AC14。

#### Scenario: AC14 验收行为

- **WHEN** 编译通过但缺必需测试/只有 waived/提前 checkbox
- **THEN** 不接受；纯说明文档可记录不适用，执行型 prompt 不自动套用，疑问转人工

### Requirement: SW31 独立输入与执行

系统 MUST 满足以下规则：接受时固定并登记独立需求/验收、实际 diff、实现及编译/测试证据版本，之后异步实际派发只读 Verifier；不只保存类型或以 Coder 报告替代独立输入。报告写入受管工件，不获得源码修复职责；下游和 Task 完成不等待，晚到报告只适用于被审版本。历史补审不重开实现或执行测试，遵守 SW19/SW27。

追踪：SW31 / AC31。

#### Scenario: AC31 验收行为

- **WHEN** 恢复旧 Task 的计数或继续运行
- **THEN** 接受后实际调度独立 Verifier，晚到报告固定旧 diff；当前代码又变化也不冒充审查新版本；历史补审不执行测试

### Requirement: SW32 审查结论与隔离

系统 MUST 满足以下规则：按验收项保存依据和缺口：有依据的不满足为 failed，无明确失败但证据缺口为 inconclusive，全部适用项有充分依据且通过才为 passed；无报告、空覆盖及执行故障单独显示，不凑 passed。合法负面结论不是模型调用失败。报告成功保存只表示记录成功，不创建 Gate、不撤销接受/完成、不触发返工或阻断 Git delivery。

追踪：SW32 / AC32。

#### Scenario: AC32 验收行为

- **WHEN** 有依据失败
- **THEN** failed；无失败但缺证据 → inconclusive；完整有据通过 → passed；无报告/空覆盖/保存失败不记 passed；任何报告不自动开 Gate/返工或撤销完成

### Requirement: R3 Verifier 有界准入

Verifier MUST 复用 R3 的单次输入/输出、Task 累计及 E05 来源恢复账；封存必需需求/diff/验证证据不能为适配模型被静默截断。模型能力未知、输入超限或预算不足时记录无法执行及原因，不生成空 passed，不撤销接受。合法 failed/inconclusive 结论不得作为失败重生成的理由。追踪 SW19/SW27/SW31/SW32、AC19/AC27/AC31/AC32。

#### Scenario: 封存输入超过可用容量
- **WHEN** 必需封存内容超出政策或实际模型容量，或容量无可靠依据
- **THEN** 保留固定来源并记录 Verifier unavailable；不截断后声称完整审查，不阻塞开发接受/交付。
