# workflow-notifications：自动化开发工作流变更

来源：[已批准 Requirement Plan](../../../../../docs/requirements/REQ00001-workflow-automation/requirement-plan.md)。以下是拟交付规范与待执行验收；按 Plan 后续确认覆盖旧来源中的人工计划审批和通知重试规则。未列出的稳定规格条款保持不变。

## ADDED Requirements

### Requirement: SW28 事件与内容

系统 MUST 满足以下规则：Task 完成事实保存后立即登记文本通知，不等待 Git、知识或 Verifier。有效人工待办产生可行动提醒，普通进度静默；同事实不重复登记，重要晚到结果关联更新。开发完成、交付、草稿覆盖和审查结论分开展示。发送结果只记已尝试/失败，不把本地 ack、零退出码、console 输出或 Teams 请求完成描述为已送达。辅助和通知失败不撤销开发完成。

追踪：SW28 / AC28。

#### Scenario: AC28 验收行为

- **WHEN** Task 已完成而交付/草稿/Verifier 尚未完成
- **THEN** 立即登记文本通知，状态分开；本地 ack 或 console 输出只记已尝试，不标已送达

### Requirement: SW29 发送与恢复

系统 MUST 满足以下规则：每个通知内容版本首次发送后，仅当 aiw-notify 明确报告网络失败时，等待 60 秒后自动重发一次；总发送次数最多两次。其他失败、结果未知及第二次发送后的任何结果均不自动重发。不假设查询、可靠幂等或送达回执，并接受这一次重发可能重复投递。发送次数、首次失败及下一次允许发送时间须持久化；重启、重渲染、时间戳变化或配置切换不刷新额度。缺配置先等待，不消耗实际发送次数。主动禁用再启用只补当前有效且依据本条仍允许发送的人工提醒，不全量补历史完成；持续启用期间仅有剩余网络重试额度的故障消息可恢复续发。过期提醒取消尚未派发的发送；在途不得伪称撤回。

追踪：SW29 / AC29。

#### Scenario: AC29 验收行为

- **WHEN** 第一次发送被明确分类为网络失败
- **THEN** 持久记录失败与 60 秒等待后最多重发一次；重启不刷新次数；非网络失败、未知或第二次失败不再自动发送

### Requirement: SW30 配置与外发边界

系统 MUST 满足以下规则：通过 aiw-notify 插件发送纯文本；首期至少提供 console 和 Microsoft Teams 两种方式，Teams 使用 send_teams_msg.py。兼容调整由插件处理，不要求维持旧脚本所有隐式默认行为。调用使用项目级显式解析配置并按项目根定位脚本，禁止缺配置时回退未知目标或凭据来源；通知版本冻结目标，变更配置不得改投旧消息。凭据仅从约定环境引用读取，不进入 argv、日志、消息或工件；不自动上传源码/日志或虚构可访问链接。Teams 验证 TLS 证书，可配置可信 CA，不以关闭验证恢复。协议只提供本地尝试/失败分类，不依赖查询、幂等或送达回执；console 和 Teams 均使用 SW29 的统一计次规则。

追踪：SW30 / AC30。

#### Scenario: AC30 验收行为

- **WHEN** 选择 console 或 Microsoft Teams 通道
- **THEN** 由 aiw-notify 发送纯文本，Teams 调用 send_teams_msg.py；缺显式配置不发，TLS/凭据/目标满足政策，结果仅已尝试/失败

#### Scenario: 网络故障重试的重启边界

- **WHEN** 首次明确网络失败后在 60 秒等待期间重启，或第二次发送仍失败
- **THEN** 恢复原 due time 和已用次数；第二次后停止，未知结果不归类为可重发的网络失败，不标记已送达。

#### Scenario: TLS 与非网络错误

- **WHEN** 证书验证失败、缺凭据、配置错误或服务明确拒绝
- **THEN** 记录失败或配置等待，不关闭 TLS 验证，不自动进行网络重试。

### Requirement: R4 受管插件协议与兼容

系统 MUST 使用有版本且绑定消息/尝试/内容身份的 stdin JSON 协议，按项目显式配置冻结目标，以环境引用读取凭据；受管 Teams 入口不得读取旧隐式 .env、默认目标/凭据或密码 argv。验证 TLS 证书和主机名，禁止自动重定向及插件内部重试，HTTP 3xx/4xx/5xx 不作为自动网络重试依据。父进程结果未知不重发；只有有类型/阶段依据的网络失败可使用原 60 秒一次恢复。旧 accepted/receipt/delivered MUST 保留为历史本地确认，不补发以追求所谓送达；新旧协议不匹配不得降级猜成功。正文上限 16 KiB，请求/结果各 64 KiB，HTTP 超时不超过 30 秒，进程等待不超过 45 秒。此要求细化 SW28–SW30/AC28–AC30/AX04。

#### Scenario: 缺显式配置且存在旧默认值
- **WHEN** 项目未配置目标/凭据引用，但旧脚本有默认值或旁边存在 .env
- **THEN** 等待配置，不读取旧默认值外发，不消耗可证明未尝试的发送次数。

#### Scenario: 重定向或协议错配
- **WHEN** 服务返回 HTTP 3xx，或插件返回旧 accepted/receipt、超限或不匹配身份的结果
- **THEN** 前者 service_failure 且不跟随重定向，后者 unknown；均不自动重发、不标已送达。

#### Scenario: 敏感远端诊断
- **WHEN** 远端错误体包含请求内容、凭据或地址
- **THEN** 仅保存固定脱敏错误码及允许的 HTTP 状态，不将原始错误体/URL/凭据写入 stdout、日志、消息或工件。

#### Scenario: 旧回执迁移
- **WHEN** 旧通知记录为 delivered 但只有本地 receipt，且发送计数无法证明
- **THEN** 保留 legacy-local-ack 与 unknown 使用事实，不虚构远端送达、不补零重发；其他安全开发继续。
