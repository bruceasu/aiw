# Problem Brief: Recommend workflow AI routing

## Problem

AIW currently uses one global AI provider and model configuration for managed
workflow execution. Different workflow stages can have different cost and
reasoning needs, but users should not need to start each Task with a complete
per-stage configuration.

## Need

Provide an initial, reviewable routing recommendation for the workflow Actors
`analysis`, `coder`, `tester`, and `verifier`. The recommendation may be
generated by an LLM or use fallback defaults when recommendation generation
fails. The `compiler` Actor remains a deterministic tool step and does not
receive an LLM routing recommendation.

## Default Routing

- `analysis=fast`
- `coder=balanced`
- `tester=balanced`
- `verifier=reasoning`

If a named Profile is absent or cannot be resolved, the affected Actor MUST
fall back to the existing global `[ai]` provider and model configuration.

## Decision Boundary

Routing recommendations are advisory only. AIW cannot guarantee that a
recommendation is accurate for a Task. AIW MUST prompt the user to review and
may adjust the generated routing plan, but an unreviewed plan MUST NOT block
`supervise`.

The first release applies routing only to Managed Workflow `supervise`.
It MUST NOT change the global provider, model, or command-line override
semantics of `aiw turn`, `aiw chat`, or CZ.

## Success Criteria

- Promotion produces a routing plan after OpenSpec artifacts and Work Items are
  synchronized.
- The plan distinguishes the `analysis`, `coder`, `tester`, and `verifier`
  Actors.
- Recommendation failure produces a stage-specific default plan.
- The `compiler` Actor remains outside LLM routing.
- Users need not configure a model for each Work Item.
- The resulting plan clearly recommends user review but remains executable.
- Missing or invalid named Profiles preserve execution through the global
  `[ai]` provider and model fallback.
- A multi-language Task compiles all affected targets and aggregates their
  diagnostics before a Coder repair attempt.

## Compile Plan

The `analysis` Actor MAY inspect repository structure, build manifests, CI
configuration, documentation, and source layout to recommend a structured
Compile Plan. The user MAY review and adjust that plan before execution, but
an unreviewed plan MUST NOT block `supervise`. The `compiler` Actor MUST
execute only the plan recorded for its request without an LLM. A
compiler failure MUST persist structured diagnostics and provide them to a
bounded Coder repair attempt.

A Compile Plan MAY reference only repository-owned compile scripts or built-in
adapters; it MUST NOT define arbitrary commands. When analysis finds that no
such selection is suitable, it MUST recommend that the user add or repair a
repository compile script and create a Gate for the unavailable Compiler
target.

For a multi-language repository, a Compile Plan MAY contain multiple targets
with path ownership. The Compiler MUST run targets affected by a Work Item's
changed paths. It MUST run every target when those paths are shared or cannot
be mapped. If multiple targets fail, it MUST persist and provide all resulting
diagnostics to the Coder in one repair handoff.

## Out Of Scope

- Automatic approval of a routing plan.
- Persisting provider credentials in Task or workflow state.
- Allowing routing recommendations to grant execution capabilities.
- Applying Task routing plans to `aiw turn`, `aiw chat`, or CZ.
