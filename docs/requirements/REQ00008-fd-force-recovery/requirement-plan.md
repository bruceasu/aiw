# Issue Plan：FD 工作流强制恢复与事件控制

Issue ID：`REQ00008-fd-force-recovery`。

状态：用户已确认需求范围，待 Issue 批准。该记录不代表 FD 移交或实现授权。

## 使用者、问题与目标

使用者是操作 AIW FD 工作流的维护者/PM。当 Agent 或 FD 流程进入异常状态时，现有受约束的正常流程不足以让操作者恢复。目标是提供一组显式的强制恢复操作：取消当前 dispatched 收据、直接修改 FD 状态，以及重新发出工作流事件，以便从异常状态恢复或有意跳过部分阶段。

## 已确认事实与来源

- 用户本轮要求新增 `aiw fd` 命令，取消当前 dispatched 事件、停止 Agent，并可重设 FD 状态及重新 emit；意图是强制恢复或跳过环节。
- 用户澄清：取消只取消收据，不保证实际停止 Agent。
- 用户澄清：状态可直设为任一已定义状态，并跳过终态校验。
- 用户澄清：可重新 emit 任一已定义事件并跳过前置条件；保留为一个 Issue。
- 稳定规格 `openspec/specs/fd-workflow/spec.md` 已定义事件收据和避免重复启动未知结果工作的规则。现有 `recover-worker` 仅覆盖确认已停止的最新 dispatched Worker 事件，并保留取消原因、后继关联及旧会话信息。
- `docs/usage/aiw-fd.md` 说明 `resume` 不会重复启动 launching/dispatched 事件；现有恢复能力不能强制设置任意状态或跳过阶段。
- 当前 CLI `aiw fd --help` 暴露 `recover-worker`、`refresh-worker`、`reopen`、`emit` 等操作，但没有通用收据取消、强制状态设置或强制 emit。
- 当前仓库 HEAD：`6f48e239607100d313e64c6dd8807d82619496e2`。

## 目标范围

在 `aiw fd` 中增加维护者使用的显式强制恢复操作，覆盖：

1. 取消当前 dispatched 事件收据。该操作不承诺终止 Agent 进程或外部会话。
2. 将 FD 状态直接设为任一已定义状态，即使正常流程会拒绝该转换或终态缺少 Reviewer 验证证据。
3. 重新 emit 任一已定义工作流事件，跳过正常流程前置条件。
4. 将上述能力作为同一组恢复工具设计和交付，不拆分 Issue。

## 非目标与约束

- 不宣称取消收据等于 Agent 已停止；调用者需自行处理原 Agent 仍运行的情况。
- 不增加任意自定义状态或未定义事件类型；“任意”限定为系统已定义的值。
- 不把强制操作表述为正常流程验收通过；强制设为 Complete 不会凭空生成 Reviewer 证据。
- 不涉及实现设计之外的 Agent 进程管理、远端 session 终止或沙箱能力。
- 当前未决定强制 emit 是否保留事件类型与 producer/target role 的结构配对校验；该问题需在 FD 工程设计中按现有事件契约处理，不得产生结构无效收据。

## 验收示例

- 对指定 FD 当前 dispatched 收据执行取消后，收据显示已取消并保留可追溯关联；系统明确该操作不代表 Agent 已停止。
- 维护者可将 FD 直接设为任一已定义状态，即使正常状态机或终态证据校验会拒绝；FD 不因此获得缺失的验证证据。
- 维护者可重新 emit 任一已定义事件，即使正常流程的状态/阶段前置条件不满足；收据仍符合定义的事件结构。
- 操作记录足以追踪强制变更的操作者、原因、目标 FD、原状态/事件和结果。沿用现有恢复命令要求说明原因的做法；具体参数与记录位置留给 FD 决定。

## 风险与工程决策

- 取消收据不终止 Agent；若原会话仍写入，重新 emit 或强制状态变更可能造成并发修改或后续结果与 FD 状态不一致。用户已明确接受“只取消收据，不保证实际停止”的语义。界面/CLI 输出应清楚说明此限制。
- 强制设置 Complete 可使状态看起来已完成，但不会补齐验证证据；归档、展示和后续操作不得把状态覆盖误报为审查通过。具体下游是否允许归档留给 FD 设计，但强制命令本身必须明确显示它跳过了校验。
- 沿用 `recover-worker` 的理由留痕模式，要求强制操作提供原因是建议的审计措施；需在 FD 中确定操作者身份的来源和记录格式。

## 规模与拆分评估

包含取消收据、强制设置状态、强制重新 emit 三种操作，但它们共同服务一个不可用/错误 FD 流程的人工恢复目标，并由同一调用者在同一工作流中使用。用户明确要求保持一个 Issue，故不拆分。实现风险和兼容影响偏高，FD 应逐项定义正常校验被覆盖的范围、仍必须成立的收据结构不变量、状态/收据一致性及审计信息。
