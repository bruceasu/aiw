# Issue Plan：aiw-exec 远程程序包执行插件

Issue ID：待 AIW CLI 分配。

状态：发现阶段；用户提出新增插件 `aiw-exec <cmd-name[@version:[os]]|URL> [cmd-args]`。当前记录是未批准草案，不代表 Issue 批准、FD 移交或实现授权。

## 使用者、问题与目标

用户希望在 AIW 中增加 `aiw-exec` 插件，使用体验类似 Node.js `npx`：调用者提供命令名（可带版本和操作系统限定）或远程 URL，以及透传给程序的参数；插件获取指定程序包及其依赖，执行目标程序，并在结束后自动删除本次下载的文件。

## 已确认事实与来源

- 用户本轮明确给出命令形式：`aiw-exec <cmd-name[@version:[os]]|URL> [cmd-args]`。
- 用户将行为类比为 `npx`，并要求从网络取得程序包和依赖、执行后自动清理下载文件。
- 用户明确表示第 1 版暂不考虑网络安全和软件包签名等校验。
- 本轮处于 Issue discovery；没有实现、FD 或 OpenSpec change 的请求。
- 当前 `aiw help --json` 显示 AIW 以插件形式扩展命令，已有 `exec-java` 插件；这只证明插件形态存在，不证明该插件的下载、依赖或执行约定。

## 目标范围

定义并交付一个 AIW 插件 `aiw-exec`，接受命令名（可选版本与 OS）或 URL 和命令参数，获取执行所需程序包及依赖，运行命令，并清理本次获取的文件。

## 非目标与约束

- 第 1 版不实现网络安全防护或软件包签名校验，按用户明确约束记录。
- 目前没有用户提出修改 AIW 核心、建立包仓库、发布服务、容器化或隔离执行环境的要求；是否需要这些能力尚不能推定。
- 本记录不授权代码修改、批准 Issue、创建 FD 或建立 OpenSpec change。

## 验收示例（待关键规则确认）

- 给出命令名及已解析的版本/OS，插件取得对应程序及所需依赖，按给定参数执行，并在结束时清理本次下载文件。
- 给出 URL 及参数时，插件能取得并执行 URL 指向的程序包，并清理本次下载文件。
- 下载、解包、依赖准备或程序执行失败时如何清理和报告，需在工程设计阶段明确；若这影响用户可观察的目标行为，应在 Issue 阶段补足。
