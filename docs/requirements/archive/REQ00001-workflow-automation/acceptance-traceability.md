# 统一验收追踪

状态：2026-09-16 临时验收矩阵。对应 [统一正文](software-requirements.md) SW01～SW34 和 [工程分组](engineering-handoff.md) E01～E08；D21/D22/D23 已确认方向，所有场景仍未执行。

R 编号链接到已有主题分析及其 Axx 实例；本文 AC 是统一补充场景，不重新编号或撤销旧实例。每行可拆为多个聚焦测试，测试名称/文件由工程规划确定。所有行执行状态均为 **未执行、待取得证据**，来源确认不等于测试通过。

## 2. 端到端关系场景（仍为待验收，不授权运行 E2E 测试）

| 验收 / 条款 | 来源及决定 | 前提与触发 → 应观察结果 | 工程 / 所需证据 |
| --- | --- | --- | --- |
| AC33 / SW33 | H04；D23 | 具体交付计划获批且范围/状态未变 → 自动执行已批准步骤，不逐步重批；新增危险动作、目标/范围变化、冲突或不明 → 停止相关交付并请求决定。未知先对账，无关文件不入提交；后台来源未保全不清理，push/PR/archive 不自动执行 | E02/E05 交付衔接；计划及授权记录、范围核验、对账、来源快照和 Git 操作记录 |
| AC34 / SW34 | H01/H03；D21 | 正式化本批 → 一个 Requirement/Task/change 内 E01～E08 分组，不按主题重复创建；某组状态/存储/恢复设计未闭合 → 不实施该部分；边界不变的字段设计由工程记录，不逐字段询问 | E01～E08；正式关联、设计/验收追踪、就绪检查及变更决定 |

AC30 / SW30 追加 D22 场景：受管调用忽略隐式 `.env`/默认目标，缺显式配置不发送；不可信证书验证失败，不以关闭校验自动恢复；可信 CA 配置按设计验证。凭据不出现在 argv/日志；旧独立调用的参数语义保持兼容。真实服务回执未经证实不得标送达。所需证据为严格模式与独立模式的契约对照、脱敏调用记录及独立获授权的 TLS/服务验证结果，当前未执行。

“端到端关系”只指本地 Workflow 状态序列推演，不扩大为集成/E2E 业务测试。

- **AX01 正常闭环：** 固定输入→Coder→报告→编译→Tester→授权计划测试→接受→释放依赖；提取/Verifier 已登记，Task 完成立即通知且不等辅助。关联 SW01～SW05、SW10～SW14、SW20、SW28、SW31。
- **AX02 恢复且不双写：** Coder 在途未知→重启核实→读取同请求结果→转交 Tester；重复观察不加模型失败，缺报告只补报告，Stop 时不新派发。关联 SW02、SW05～SW08、SW16。
- **AX03 授权与证据分离：** 获批范围内新增 fixture→自动发现→旧通过失效→重验；实际操作变危险则等待新授权，不能以相同 argv 或“仅测试修改”绕过。关联 SW03、SW11～SW13。
- **AX04 完成后的辅助失败：** 开发完成→部分草稿/Verifier 故障/通知超时→各自预算及状态保持，开发不返工，重要结果只关联更新；无幂等不自动重复外发。关联 SW19～SW21、SW28～SW32。
- **AX05 历史与知识版本：** 可用旧证据复用→相关历史回填达到累计上限→停可选工作；来源变更产生新候选，旧审阅不继承，历史 prompt 原样可追溯。关联 SW04、SW21～SW27。

## 3. 工程证据登记要求

正式实施项应引用 SW/AC/AX，并记录实际测试/静态检查的文件位置、命令、输入版本、计划及授权、结果、未执行原因与缺口。未执行、失败、过期和不适用分开；结构检查、清单勾选和本文存在都不构成功能通过。

验收方法优先按 E 分组设计确定性状态/预算/版本聚焦用例；真实进程、崩溃恢复及外部服务测试要另外明确命令、范围与权限。外部通知协议未核实前只能验证本地保守状态机，不能宣称真实送达/严格去重。
