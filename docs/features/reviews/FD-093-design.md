# FD-093 独立设计反馈

- 结论：**ready**，可按 FD Revision 2 实施。
- 范围：仅有界静态设计检查；未领取设计事件，`source_event` 为 null。本报告不构成实现验证或状态变更。
- 依据：当前 FD、包管理稳定规范，以及 build.py、LocalPackages、Operation、Manager、repository、archive 的相关调用路径。

## 设计判断

单次多根 Operation 复用现有全图预检和逐包事务，是局部且合适的优化。先登记全部显式根再展开依赖，可让共享成员只访问一次，并保持显式根为 manual、仅依赖为 auto、已有 manual 不降级。保留单根 CLI 接口和 update 的 collection 成员裁剪逻辑，无须改变安装记录格式。

Manager 的同指纹分支移到临时载荷生成之前是安全的，前提是仍处于现有安装锁内，且保留锁入口对未完成事务的拒绝。Operation 已持有同一 Manager 锁，嵌套 locked 仅复用该锁。平台、输入 ZIP 覆盖、脚本解释器检查不能被快路径跳过；同指纹仍需保存 reason、dependencies 和实际 members。

LocalPackages 可由同一份已验证 prepared 数据同时生成 entry 和文件列表，避免重复解压，不必长期保留完整 payload。fetch 对原路径、原始长度和 SHA-256 的复查可以证明与原 entry 的已验证包字节一致；Operation 随后仍完整解析一次并持有 prepared 数据直到安装结束，保留更新包管理器自身时的载荷和脚本固定语义。

## 实施必须保留的约束

1. 多根输入若包含同名不同版本，必须报错，不能由后一个覆盖 selected；同名同版本可以去重。不得把整个 catalog 变成显式根。
2. 仍在任何包写入前完成全图平台、版本、成员、循环、归属和最终状态检查。运行期钩子失败依然只保证逐包事务，不承诺全操作回滚。
3. FD 已明确单次操作总 ZIP 大小受 512 MiB 限制。这会使过去分多次 Operation 可安装的超大 install all 改为整体预检失败；实现时须在说明中明确该范围，不能静默按包分批绕过限制。静态未取得实际包体积，不能保证当前 all 一定低于限额。
4. 原 ZIP 检查不能只依赖 mtime/size，也不能在第一次获取后盲信路径。路径链接检查与长度/哈希必须同时保留；Operation 的 prepared 数据不得在安装中途重新延迟读取磁盘源码或包文件。
5. 已安装快路径保留当前校验和记录语义，不额外引入跳过损坏文件检查或修改安装锁模型的策略。
