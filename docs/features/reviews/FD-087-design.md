## 判断依据

1. `build <target> --compile-version snapshot-X --version 1.0.1` 明确分开原生产物来源和包身份，保留现有显式 `--version` 重新编译的行为。无需扩大到 publish 或新增版本存储系统。
2. `latest_compile(target, source)` 已具备精确版本过滤、组件覆盖检查和原生产物 SHA-256 检查。显式来源必须先通过该检查；不存在或失效时直接失败，禁止调用编译器或进入包、暂存仓库及清单写入路径。
3. `package_component`、`build_component`、旧程序打包路径均把传入版本用于包路径和元数据；依赖与集合成员也显式使用同一版本。实现需让全部调用传递包版本，原生文件直接从既有 `bin` 读取，不能改写嵌入版本或编译记录。
4. 显式来源版本应独立于 `AIW_VERSION` 选择；包身份优先级为 `--version`、非空 `AIW_VERSION`、选中的来源版本。无 `--compile-version` 时保留现有 FD-086 分支与优先级。
5. 所有成功构建清单，包括组件、目标和 `all` 的分组清单，应在既有包 `version` 外记录可选 `compile_version`。`latest` 继续读包版本，`latest-compile` 继续读编译记录；旧清单无需迁移。
6. 编译记录按目标保存，重叠原生产物会使旧记录失效，并非历史版本归档。FD 已明确只复用仍有效的当前输出，也明确源代码与资源使用当前工作区，未承诺历史源码或原生版本与包版本相同。
