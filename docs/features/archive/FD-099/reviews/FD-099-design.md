- 结论：ready
- 设计版本：Revision 2
- 来源事件：FD-099-000002-design-requested
- 方式：一次有界、只读静态设计审查；仅写本报告与 JSON 证据。

设计满足用户要求，工作项规模与依赖合理，无阻断发现。

参数处理先移除唯一的 `--push`，再沿用现有 `--new` 位置和分支数量检查，可以支持两种模式下的任意开关位置并保留原默认行为。重复开关和未知选项应在 preflight 及 Git 状态变更前拒绝。

当前 `main` 的源合并、worktree remove 和临时父目录清理均已有失败退出路径。将可选 push 放在这些步骤全部成功之后，可保证合并或清理失败不触发推送。`--new` 单源创建也能沿成功路径执行，不能把是否执行 merge 循环作为推送条件。

完整目标 refspec 与显式 origin 避免误推调用方分支；`--no-follow-tags` 和 `--recurse-submodules=no` 限定推送范围。该方案不添加强推、upstream、fetch、重试或回滚，失败保留本地已完成合并并返回非零，范围清楚。

实现需在 push 前输出本地成功信息，使 Git 非零退出、OSError 或中断均不会让用户误以为本地合并被撤回。这是现有验收要求的实现注意点，无需扩大设计范围。

已读取 FD、脚本的 parse_args/preflight/main/git 与恢复路径、稳定规范 Git merge-to requirement 和 CLI 文档对应小节。现有规范与帮助中的“不 push”陈述需要按工作项 1.2 同步为默认不 push、显式开关才推送。

本轮未执行测试、编译、脚本功能、Git 命令或网络请求。设计结论不代表实现验证通过；剩余运行风险为 Git 认证、远端可用性及非快进拒绝，由实现中的失败返回和本地保留语义处理。
