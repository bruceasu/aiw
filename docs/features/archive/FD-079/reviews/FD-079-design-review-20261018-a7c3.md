## 已有设计的充分部分

独立子模块与 plugin 包装符合现有边界；CLI 的 ACTION、命名输入优先、重复输入、stdout 和删除限制已保留 Issue 确认规则。全包暂存后再输出可满足多文件或链接输入时 stdout 零输出要求。`-l` 与 `-L` 分开、受约束路径访问、覆盖仅限普通文件、输出关闭后才删除源，方向合理。无需改变通用 plugin 分发接口。

## 阻塞项

### G1：外部授权和可行性 Gate，不能当作设计错误

两个新增依赖及一次固定版本下载仍待人工授权。BZIP2 writer API、许可证、传递依赖尚无本地源码证据。保持 Gate；审阅不豁免授权，也不要求绕过网络限制。1.1 完成前不得 design-ready。

### D1：归档路径与重名策略尚未定义

Issue 的 `pack a.txt b.txt` 示例明确把归档内部路径交给 FD，但 FD 只有“以逻辑名入包”，未定义目录输入是否包含顶层目录、绝对/跨目录输入如何命名，以及不同输入具有相同 basename 时如何处理。全清单冲突验证也缺少规范化后重复条目、大小写折叠冲突及文件/子目录祖先冲突的规则。

建议在 1.4/1.7/1.8 明确：归档根路径映射，按目标平台适用的规范化规则检测冲突；无法无损唯一映射时在输出前报错，`-O` 不用于化解包内重复条目。覆盖不能依赖条目顺序决定最终内容。补充同 basename、多层目录和 `a` 与 `a/b` 冲突示例。

### D2：格式与编码矩阵是实际可行性决策，不能留给 Worker 猜测

本地 `compress/gzip/gzip.go:106–113` 明确 GZIP 字符串为 Latin-1，标准库写入非 Latin-1 字符串会报错。FD 尚未说明默认 UTF-8 文件名如何映射到 GZIP FNAME，也未明确解包纯 GZ/BZ2 的文件名来源；TAR 历史字节名与 PAX UTF-8 元数据的选择同样仍未定稿。这些限制独立于 BZIP2 下载是否成功。

1.1/1.3 必须给出 ZIP、TAR、GZIP、BZIP2 的读写矩阵，明确 UTF-8 标志、原始字节和扩展头优先级，以及 GZIP 有/无 FNAME 时的输出名。选择合法格式策略或明确报错，不能静默转码或伪称所有格式均原生支持任意编码。Big5-HKSCS 的能力取舍按用户已授权回退处理；非法字节解码不得静默替换。

### D3：暂存资源和失败边界尚未定稿

FD 明确写“具体容量上限及失败清理在设计审阅前定稿”，当前没有数值或无上限决策。全包输入加解压暂存可能耗尽磁盘；ZIP 声明大小不代表实际解码量。stdout 的预检还必须验证内容解码和校验和成功，不能只数中央目录条目。

在 1.7/1.8 明确实际写入字节数、条目数及路径长度等资源策略，或明确选择受磁盘容量约束、无固定上限并记录理由；明确磁盘满、坏 checksum、截断和暂存关闭失败时不发布 stdout、不触发 `-d`。失败清理仅删除本次拥有的资源，已有目标及其他进程文件不能进入清理范围。固定容量若改变用户可用范围，应明确记录产品影响。

### D4：源与输出重叠及删除时源身份需要具体规则

已有条款禁止同文件和 `-d` 输出在源内，但未决定普通 pack 输出位于输入目录内时如何避免把新输出、旧输出或临时文件再次打包。`-d` 只在全成功后执行仍不能防止源在打包期间被替换后误删新文件，或重叠多输入重复删除。

1.4/1.9 应明确拒绝或安全排除输出及临时文件的规则；建议输出处于输入树内直接拒绝，避免隐式漏包。删除源前重查已记录身份；身份变化应保留源、返回失败，不能删除替换后的路径。重叠输入可明确拒绝或去重，但需保留路径报告的确定性。不能用字符串前缀代替实际路径与文件身份判断。
