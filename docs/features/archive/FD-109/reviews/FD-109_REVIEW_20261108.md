### F1 — 直连 Gateway 在请求未启动时写入无法恢复的执行状态（High）

[openai_codex.go](/D:/03_projects/AI-tools/aiw/.wt/FD-109/src/programs/agent-gateway/openai_codex.go:14) 将结果初始状态设为 `failed`。当 AIW 凭证不存在/失效而 `OpenAICodexResponses` 在 `OnStart` 前返回错误，或上下文在开始前取消（第 29 行）时，`finish` 会把该状态写进记录，但 `StartedAt` 为空（第 23 行）。

[storage.go](/D:/03_projects/AI-tools/aiw/.wt/FD-109/src/programs/agent-gateway/storage.go:93) 的恢复逻辑仅接受未启动记录状态 `reserved` 或 `spawn_failed`；第 95 行要求 `failed`、`cancelled` 等终态必须有 `StartedAt`。因此一次常见的“尚未登录”请求、开始前取消或开始前存储错误，会留下 Gateway 下次启动时拒绝加载的元数据，导致服务无法正常重启。

**建议：** 所有 `StartedAt == nil` 的终结路径应持久化为既有的 `spawn_failed` 状态（保留独立 HTTP 错误码供响应/审计使用），或采用一个明确兼容的存储状态转换，并确保存储恢复规则一致。覆盖凭证缺失和开始前取消的黑盒验证仍需后续经授权执行；本次仅基于状态机静态追踪。
