# FD-103 独立设计审阅

结论：ready。审阅对象为 FD-103 Revision 2 及本次有界审阅内 Planner 补充的迁移边界、worktree 路径发现与索引事务规则，来源事件为 `FD-103-000002-design-requested`。本报告仅为设计证据，不代表实现验证通过。

## 已确认的设计依据

`src/plugins/aiw-fd.py` 的 `update_index` / `write_index` 在状态操作后重写同一个受跟踪的 `FEATURE_INDEX.md`。跨 worktree 的锁无法使 Git 分支中的共享表格修改互相独立。固定全局导航、每个 FD 拥有局部目录且常规状态事件不改索引，能够移除此处的必然写入重叠。继续使用标准 Git 合并及现有真实冲突恢复路径，范围合理。

## 本次审阅发现及处理

### D1：迁移后的 Markdown 相对链接兼容机制尚未确定（高）

方案要求历史正文原样移动，同时保留引用；但 CLI 的旧 artifact 路径映射只影响 CLI 文件读取，无法修复普通 Markdown 渲染器中的相对链接。把活动设计从 `docs/features/` 移到 `docs/features/FD-ID/` 会使 `../`、`../../` 或 `FD-OTHER_*.md` 等目标的解析基准改变。原位不动的历史归档已有失效链接不属于本次新增问题；需要单独识别本次移动新增的断链。

建议：WI 1.3 明确对本次移动文件的链接分类处理。活动设计允许仅改链接目标且保留正文语义；已签发历史报告保持原字节，以不改历史报告的局部导航提供来源路径及实际目标映射。若要求历史报告中的每个链接直接可点击，则需要选择能保留旧解析基准的兼容措施；不能只用“风险记录”替代用户的引用保留要求。明确哪些旧链接受支持以及任何有意的破坏性变化。

处理：Planner 明确本仓库仅移动活动 FD-103 及本轮设计报告；既有历史记录全部留在原归档路径。同步当前文档引用，第三方旧布局兼容读取和操作，不隐式批量迁移。CLI artifact 映射与浏览器书签明确区分，物理路径变化写入迁移说明。此边界消除了批量移动历史正文带来的新增断链风险；实施仍须同步本轮实际移动记录的当前链接。设计问题已解决。

### D2：worktree 创建及交付仍依赖平铺 FD 发现（高）

`src/plugins/aiw-git/git-wt.py:86` 的 `workspace()` 与 `:141` 的 `worktree_add()` 均只匹配 `docs/features/FD-ID_*.md`。如果 WI 1.1 仅修改 FD CLI，新布局的计划无法创建 worktree，既有注册 worktree 的交付和清理也会在 `workspace()` 被拒绝。

建议：将这两个入口显式纳入 WI 1.1 和静态验收；新旧布局均可读，两处并存或同 FD 多个候选必须明确拒绝，保留提交检查、父工作区干净要求及符号链接安全检查。当前方案范围仅写“FD CLI、shell 补全”，应明确包含 Git worktree 插件。

处理：Planner 已将 Git worktree 插件两处扫描明确纳入 WI 1.1。设计问题已解决；实现审阅应追踪这两条调用路径。

### D3：局部 index.md 的归档与再次归档事务需要具体规则（中）

`close_locked()` 当前只快照并恢复全局索引，`evidence_moves()` 当前只搬迁旧共享 reports/reviews。新布局会同时存在活动 index、已存在的归档 index、历史证据和新证据。reopen/request-review 后保留归档证据是既有契约；再次 close 时归档 index 已存在是正常情况，不能把它作为证据碰撞拒绝，也不能覆盖真实证据。

建议：WI 1.2 明确预检新旧证据源的重复目标；历史报告碰撞必须拒绝。局部 index 是可再生导航，可在快照后为目标 FD 重建，其覆盖与源 index 删除均纳入同一回滚。回滚恢复设计、两侧 index、全部已移动证据及收据；不扫描或改写其他 FD。补充“reopen → 新证据 → 再 close”和“index 写入失败”的静态验收路径。局部 index 指向整个 reports/reviews 目录能避免每份报告产生额外索引更新。

处理：Planner 补充 active 与 archive 两侧 index 快照；允许覆盖明确生成的归档 index，保留多个历史设计链接，失败时还原两侧 index。该规则区分了可再生导航与不可覆盖的历史证据，设计问题已解决。实施须保持原证据碰撞预检及失败回滚。
