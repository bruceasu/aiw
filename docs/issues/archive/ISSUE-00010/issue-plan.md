## 使用者、问题与目标

为命令行用户提供 Go 实现的独立压缩、解压与打包工具，并包装为 AIW plugin。用户需要在现代跨平台文件名与历史编码压缩包之间工作，并支持管道输入输出。

源代码位置由用户指定为 `src/programs/aiw-packer`。独立可执行入口与 plugin 应提供同一套行为；依据现有 `aiw-<name>` 约定，建议入口为 `aiw-packer` 与 `aiw packer`，尚待后续设计核对安装集成方式。

## 用户明确要求

### 格式

pack 与 unpack 的目标支持范围：ZIP、TAR、TAR.GZ/TGZ、TAR.BZ2、GZ、BZ2。

pack 默认格式为 ZIP；unpack 默认自动检测格式。TAR 本身作为打包格式保留，不因无压缩而排除。

### 参数

| 参数 | 需求与边界 |
| --- | --- |
| `-h/--help` | 输出使用说明 |
| `-f/--format` | 指定格式；pack 默认 zip，unpack 默认自动检测 |
| `-e/--encoding` | 文件名编码，默认 UTF-8；同时用于 pack 写出和 unpack 读取；指定编码不受支持或无法表示文件名时明确报错，不静默替换字符 |
| `-i/--input` | 文件、目录或压缩文件；`-` 表示 stdin；pack 可重复指定多个输入；unpack 重复指定时报错；未指定时使用位置输入 |
| `-o/--output` | 压缩输出文件或解压目录；`-` 表示 stdout；可省略并推导默认路径 |
| `-O/--overwrite` | 允许覆盖同名普通文件；目录继续合并；文件/目录类型冲突或已有目标为符号链接时报错；不为覆盖删除已有目录，不放开其他安全限制 |
| `-c` | pack 强制输出 stdout；unpack 与 `-o -` 同规则：只允许目录和恰好一个普通文件；多个文件、链接或特殊条目均在写出任何内容前报错 |
| `-d/--delete` | 仅在整个操作成功后删除源；stdout 禁止；删除失败时保留输出、报告未删除路径并返回非零退出码；pack 成功后删除源文件或递归删除源目录，多输入须全部成功后才开始删除；stdin 禁止 |
| `-l` | 保存/恢复符号链接本身，不跟随目标；首版仅支持范围内相对链接，拒绝悬空链接，创建失败报错；stdout 解包不接受链接条目 |
| `-L` | 已确认仅用于 pack，读取目标内容并以链接名入包；与 `-l`、`-d` 互斥；循环、悬空或越界目标报错 |

原文 `-o required` 与省略时推导路径的歧义已通过后续确认消解：常规输入可省略并按已确认规则推导，stdin 必须显式指定 `-o` 或 `-c`。已确认长参数使用 `--output`，不保留原文拼写 `--ouput`。

### 位置参数

1. 存在位置参数时，第一个是 ACTION，只支持 `pack|unpack`。
2. 后续位置参数作为输入的后备来源；pack 可接受多个。已确认：指定 `-i` 时仅使用命名输入，不使用位置输入；未指定 `-i` 时才使用位置输入，两者不合并。
3. unpack 未指定 `-i` 时，仅使用 ACTION 后第一个输入，即原文的第二个位置参数，忽略其余输入；指定 `-i` 时使用命名输入。
4. ACTION 后可以没有位置输入，此时使用命名参数。已确认：pack 允许重复 `-i`，多个命名输入共同打包；unpack 只允许一个 `-i`，重复指定即报错。
5. 完全没有位置参数时，ACTION 默认 pack；仍必须通过命名参数给出有效输入。
6. 已确认：选项允许出现在 ACTION 前后；支持 `--` 结束选项解析，之后的内容按位置参数规则处理，不再作为选项。

不能把 `aiw-packer file.txt` 未经确认解释为隐式 pack：按用户当前规则，`file.txt` 在 ACTION 位置。

### 默认路径

- pack 单输入：输入名追加对应格式后缀。
- 已确认：pack 多输入且省略 `-o` 时，在当前工作目录生成 `archive.<格式后缀>`；同名文件已存在时默认报错；显式 `-O` 时允许覆盖。GZ/BZ2 仍按已确认规则拒绝多输入。
- 已确认：unpack 默认目录剥离完整格式后缀，例如 `backup.tar.gz`、`backup.tgz`、`backup.tar.bz2` 均解到 `backup/`；允许使用已有目录；同名文件默认报错，显式 `-O` 时允许覆盖。
- 已确认：stdin 输入（`-i -`）必须显式指定 `-o` 或 `-c`，否则报错，不推导输出路径。`-c` 用于 unpack 时仍受单文件限制。
- 已确认：stdin 打包为 ZIP/TAR 时，归档内部文件名默认 `stdin`；TAR.GZ/TAR.BZ2 沿用 TAR 内部条目规则。此规则不为 GZ/BZ2 引入 TAR 包装。
- 复合后缀剥离与解包同名文件规则已确认；其他输出冲突及安全边界见待决问题。

## 工程可行性与候选规则（尚未批准）

- 已确认：`-e/--encoding` 同时支持 pack 写出和 unpack 读取历史文件名编码。用户理由：部分环境的解压工具很旧，需要打包端也能生成兼容的文件名。历史编码范围按本轮增补整理为 CP437、Shift_JIS，以及优先 Big5-HKSCS、不支持时接受 Big5；优先 GB18030、不支持时接受 GBK。用户原文 big5-hkcsc 按 Big5-HKSCS 理解，此名称归一为整理者解释。已确认默认 UTF-8；指定编码不受支持或无法表示文件名时明确报错，不静默替换字符。Big5/GBK 回退仅指实现能力的取舍，不授权运行时静默改用其他编码。已确认编码只作用于文件名，不转换文件内容；格式没有文件名元数据时不应用编码转换，并在帮助中说明。各格式具体元数据映射和实现能力由 FD 核实。
- 已确认：GZ/BZ2 遇到目录或多个输入时报错，并提示使用 TAR.GZ/TAR.BZ2；不自动转格式，也不逐文件分别输出。来源：用户对本轮问题的明确答复。单个普通文件与 stdin 仍在支持范围内。
- 自动检测建议基于内容，不能仅依赖后缀；stdin 检测与 ZIP 的可寻址读取可能影响缓存和临时文件策略，留给 FD 比较方案。已确认多文件 stdout 解包必须零输出后报错；对于流式归档，需在 FD 设计时据此评估预扫描或暂存方案，不得用逐文件直出破坏该规则。
- BZ2 写入、历史编码转换的实现方式与依赖尚未核实；本阶段没有批准新增依赖、下载或调用系统工具。GB18030 为优先目标，GBK 是用户明确接受的能力回退；用户接受 Big5-HKSCS 不支持时回退到 Big5；必须明确实际支持范围，不能把 Big5 宣称为完整 Big5-HKSCS。
- 已确认所有场景默认不覆盖已有文件，显式 `-O` 时允许覆盖；解包允许使用已有目录。禁止解包路径越界、输入输出指向同一文件；使用 `-d` 时，输出不得位于将被删除的源目录内。覆盖开关不放开上述边界。`--overwrite` 是对用户原文 `--overwirte` 的正确拼写整理，未要求提供该拼错别名；已确认覆盖仅限同名普通文件，已有目录继续合并；文件/目录类型冲突或已有目标为符号链接时报错，不为覆盖删除已有目录及其内容。该限制只约束 `-O`，不改变 `-d` 成功后递归删除源目录的规则。
- 已确认：`-d` 仅在整个操作成功后删除源；输出到 stdout 时禁止使用 `-d`，同时覆盖 `-c` 与 `-o -`。来源：用户对上一轮删除规则问题回复“好的”；本轮据此整理。输出关闭应属于成功条件，是待 FD 细化的工程要求。后续已确认删除失败处理：保留输出，报告未删除路径并返回非零退出码。

## 验收示例

以下是需求示例，未执行，也不是测试通过记录：

- `aiw-packer -i report.txt`：默认 pack 为 ZIP，输出建议为 `report.txt.zip`，文件内容保持不变。
- `aiw-packer pack a.txt b.txt -o bundle.zip`：两个位置输入进入同一个 ZIP；归档内部路径规则由后续设计明确。
- `aiw-packer pack a.txt b.txt`：默认 ZIP，在当前工作目录生成 `archive.zip`；未带 `-O` 且文件已存在时，报错并保留已有文件。
- `aiw-packer pack -f tar.gz a.txt b.txt`：在当前工作目录生成 `archive.tar.gz`；未带 `-O` 且同名文件已存在时，报错。
- `aiw-packer unpack bundle.zip ignored.zip -o extracted`：只解压 `bundle.zip`，忽略其余位置输入。
- `aiw-packer pack ignored.txt -i selected.txt -o selected.zip`：仅打包 `selected.txt`，不把位置输入 `ignored.txt` 合并进包。
- `aiw-packer pack -i a.txt -i b.txt -o bundle.zip`：将两个命名输入打包到同一个 ZIP；若另有位置输入，不与命名输入合并。
- `aiw-packer unpack -i a.zip -i b.zip -o extracted`：重复指定命名输入，报错；即便两次值相同，也不符合只允许一个 `-i` 的规则。
- `aiw-packer unpack ignored.zip -i selected.zip -o extracted`：仅解包命名输入 `selected.zip`。
- `aiw-packer unpack -i bundle.zip`：自动检测格式；默认目录为 `bundle`。
- `aiw-packer unpack -i backup.tar.gz`、`aiw-packer unpack -i backup.tgz`、`aiw-packer unpack -i backup.tar.bz2`：均剥离完整格式后缀，默认目录为 `backup/`。
- 解包目标目录已存在且没有同名文件时允许使用；同名文件未带 `-O` 时报错并保留，带 `-O` 时允许覆盖。是否预检全部冲突以及失败后新文件的处理方式尚待 FD 明确，不宣称已有事务性回滚。
- `aiw-packer pack -f tar.gz -i folder -o folder.tar.gz`：按选定格式打包目录；TGZ 为同类格式别名。
- `aiw-packer pack -f gz -i folder -o folder.gz`：输入为目录时报错，提示使用 TAR.GZ；BZ2 对目录同样报错并提示 TAR.BZ2。
- `aiw-packer pack -f bz2 a.txt b.txt -o bundle.bz2`：多输入时报错，提示使用 TAR.BZ2；GZ 同样拒绝多输入并提示 TAR.GZ。
- TAR、TAR.BZ2、GZ、BZ2 的正常 pack/unpack 均须覆盖其支持范围。
- `aiw-packer unpack -e <legacy-encoding> -i old.zip -o restored`：使用已支持的显式编码处理历史文件名，不改变文件内容。
- 未指定 `-e` 时使用 UTF-8；显式指定未支持的编码时报错，不自动改用其他编码。
- 对没有文件名元数据的格式，已支持的 `-e` 不引入编码转换；帮助说明其不适用，不将内容当作文本转码。不同 `-e` 值均不得改变原始文件内容。
- pack 时文件名含指定编码无法表示的字符，明确报错，不用问号或其他替代字符生成损坏的文件名。
- `aiw-packer pack -e <legacy-encoding> -i folder -o legacy.zip`：按已支持的指定编码写出文件名，以供旧版解压工具使用；历史编码范围见上，各格式适用范围待确认。
- 若提供 Big5-HKSCS，其 pack/unpack 验收应包含 HKSCS 扩展字符文件名；若不能支持，用户接受仅提供 Big5，但必须明确能力范围，不能宣称 HKSCS 已支持。具体样本由 FD 明确。
- 优先提供 GB18030 双向文件名编码；若不能支持，允许仅提供 GBK 并明确列出支持范围，不宣称 GB18030 已支持。
- `aiw-packer pack -f gz -i - -o -`：stdin 输入、stdout 输出；错误与诊断不能混入压缩数据。
- `aiw-packer -i -`：缺少显式 `-o` 或 `-c`，报错，不创建默认输出。
- `aiw-packer pack -i - -o stream.zip`：从 stdin 读取内容，ZIP 内部唯一文件名为 `stdin`。
- `aiw-packer pack -f tar -i - -c`：输出 TAR 到 stdout，内部唯一文件名为 `stdin`。
- `aiw-packer unpack -i -`：缺少显式 `-o` 或 `-c`，报错；不得按压缩包基本名推导目录。
- `aiw-packer unpack -c -i one.zip`：包内仅含目录与恰好一个普通文件时，将普通文件内容输出到 stdout；目录条目不计数，`-o -` 行为相同。
- 包内没有普通文件时，不满足“恰好一个”条件，拒绝 stdout 解包。
- 包内虽只有一个普通文件，但另有符号链接、硬链接或特殊条目时，`-c`/`-o -` 解包均报错，stdout 不写出任何内容，即使指定 `-l` 也不例外。
- `-l` 或 `-L` 遇到悬空链接时报错；不得静默跳过、输出目标路径代替文件内容或触发源删除。解包 `-l` 的存在性校验应考虑归档中稍后出现的目标条目，不应因条目顺序产生误判。
- 包内有两个或更多普通文件时，`-c` 和 `-o -` 均报错，stdout 尚未写出任何内容；不能先输出第一个文件再发现第二个。
- `-d`：整个操作成功后才删除源；pack/unpack 操作失败时不执行源删除。
- `aiw-packer pack -c -d -i report.txt` 与 `aiw-packer pack -d -i report.txt -o -`：拒绝 stdout 与删除源的组合；建议在写入或删除前报错。
- 压缩或解压已成功，但 `-d` 删除源失败：保留已生成的输出，报告未删除的源路径，返回非零退出码；不得将其报告为压缩/解压本身失败并丢弃输出。
- `aiw-packer pack -d -i folder -o folder.zip`：整个打包成功后递归删除源目录 `folder`，保留 `folder.zip`。
- `aiw-packer pack -d -i a.txt -i b.txt -o bundle.zip`：两个输入全部打包成功后才开始删除；任一打包失败不得启动源删除。删除阶段自身不承诺事务性回滚，失败仍遵守已确认的残留路径与非零退出码规则。
- `aiw-packer pack -d -i - -o stream.zip`：stdin 与 `-d` 组合报错；建议在读取输入或写出结果前拒绝。
- `aiw-packer unpack -d -i bundle.zip -o extracted`：解包整体成功后删除源 `bundle.zip`，保留解包结果。
- 独立入口与 `aiw packer` 使用一致的参数语义，支持 `-h/--help`。
- `aiw-packer -f zip pack a.txt --output bundle.zip`：允许选项位于 ACTION 前后，等价于对应的普通 pack 调用。
- `aiw-packer pack -o bundle.zip -- -draft.txt`：`--` 后的 `-draft.txt` 是位置输入文件名，不作为选项。
- `--ouput` 不作为 `--output` 的兼容别名，使用时报告未知选项。
- `aiw-packer pack -O -i a.txt -o bundle.zip`：允许覆盖已有 `bundle.zip`；`aiw-packer unpack -O -i bundle.zip -o extracted`：允许覆盖目标目录内同名文件。
- 即使带 `-O`，输入输出为同一文件、解包路径越界、`-d` 输出落在待删除源目录内时仍拒绝。
- 包内普通文件 `report` 与目标目录 `report/` 冲突时，即使带 `-O` 也报错，不删除 `report/` 及其内容；反向文件/目录冲突同样报错。
- 目标同名条目为符号链接时，`-O` 报错，不跟随链接覆盖目标，也不替换该链接；该规则不禁止 `-l` 在无冲突位置恢复已验证的安全链接。
- 已有普通文件可用 `-O` 覆盖，已有目录可继续合并；这不改变 `-d` 在整个打包成功后删除源目录的已确认规则。
